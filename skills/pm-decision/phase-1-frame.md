# Phase 1 — Frame the Problem

**Goal:** single, defensible problem statement before any solution thinking.

## Define
Push hard until each is answered:
1. What is the customer actually trying to accomplish? (underlying job, not feature)
2. Who specifically has this problem? (which clients, roles, workflows)
3. Why now? (what changed)
4. How painful? (hair-on-fire vs nice-to-have)
5. What does "solved" look like in 3 months?
6. Business case? (revenue, retention, differentiation)
7. What are we NOT solving? (explicit boundaries)

## Challenge
- Is this unique or replicating something existing?
- Why are we the right team?
- What happens if we don't build this?

## Building it for yourself

If the user is the user, the rules change and it is worth saying out loud:

- You can introspect the need directly, so you may move closer to a solution faster than you would
  for someone else.
- The discipline shifts from *research* to *honesty*. There is nobody to interview and nobody to
  contradict you, which means the failure mode is a problem statement shaped to fit what you already
  want to build.
- **Prove or kill it on yourself, fast.** Question 7 (what we are NOT solving) does the heaviest
  lifting here, because a personal tool with no written non-goals grows until it is unmaintainable.

## Done when
Problem fits one sentence. User agrees. Scope boundaries explicit.
